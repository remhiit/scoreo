# Architecture Decision Records

An ADR records **one decision the code cannot tell**: what was removed (an old schema version, a
deleted field), the rules of a contract, or why a choice was made. What the code already says — a
type, a function's behaviour, a file layout — does not get an ADR; it is read in the code (types and
JSDoc included).

## Format

One file per decision: `doc/adr/NNNN-short-title.md` (four digits, lowercase kebab-case title). A
front matter header, readable by a person and by `scripts/check-adr.mjs`, then the content:

```markdown
---
title: <the ADR's title>
decision: <the decision in one sentence>
status: Accepted            # Accepted | Superseded by ADR-NNNN | Deprecated
date: 2026-11-08            # date of the decision
supersedes: ADR-NNNN        # optional
sources: commit abc1234, issue #642, PR #646   # optional
---

## Context
## Decision
## Consequences
```

- `title`, `decision`, `status` and `date` are required; `supersedes` and `sources` are optional.
- `sources` cites where the decision comes from: the commit that applied it, and the issue and PR when
  they exist. When the origin cannot be found in git, it says so ("origin of the decision not found")
  and `date` is the first commit applying it.
- English, like the rest of the technical documentation.

## Life cycle

- Numbers are sequential and never reused: the order of numbers is the order of decisions, so dates
  never decrease from one number to the next. Two decisions from the same commit are numbered in the
  order they appear in their source.
- An accepted ADR is never rewritten in substance. Changing one's mind is a new ADR with
  `supersedes: ADR-NNNN`; the old one only changes its `status` to `Superseded by ADR-MMMM`. A
  decision no longer current with no replacement becomes `Deprecated`.
- A new ADR is written in the PR that applies the decision; the merge is the acceptance (there is no
  "Proposed" status). Its `sources` cite the issue, and the PR if it already exists.
- A converted decision that today's code contradicts describes what was decided at the time, with
  `Superseded by` (when a later decision, also an ADR, replaced it) or `Deprecated`.

## Checks

`node scripts/check-adr.mjs` (CI job `adr`) fails when a number is missing or duplicated, dates
decrease in number order, a required header field is missing, a `status` is not one of the three
values, a `supersedes` and the matching `Superseded by` do not answer each other or name an absent
ADR, or the index below differs from the files. `node scripts/check-adr.mjs --write` regenerates the
index. `scripts/check-doc-links.mjs` checks the links of `doc/adr/` like the rest of `doc/`.
